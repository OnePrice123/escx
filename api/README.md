# escx-api

Подписки, вход и доступ. Cloudflare Worker + D1.
Обоснование архитектуры — `docs/07-billing.md`, почта — `docs/08-mail.md`.

## Запуск тестов

```bash
node test/test.mjs      # 166 проверок, сеть не нужна
```

D1 подменяется заглушкой, `crypto` берётся из Node — тесты идут где угодно.
Последний раздел вызывает Worker целиком, через его собственный `fetch`: маршруты
ломаются тише всего, и проверять их отдельно от обработчиков смысла нет.

## Развёртывание

```bash
bash setup.sh
```

Скрипт идемпотентный: ставит wrangler, гоняет тесты, создаёт базу D1,
вписывает её идентификатор в `wrangler.toml`, применяет схему, создаёт перец для
паролей, спрашивает остальные секреты и публикует. Повторный запуск ничего не ломает —
в частности, уже существующий `AUTH_PEPPER` не перезаписывается.

Вручную, если нужен контроль по шагам:

```bash
wrangler login
wrangler d1 create escx                 # id из вывода вписать в wrangler.toml
wrangler d1 execute escx --file=schema.sql --remote
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))" | wrangler secret put AUTH_PEPPER
wrangler secret put PADDLE_WEBHOOK_SECRET
wrangler secret put RESEND_API_KEY
wrangler deploy
```

Домен для запуска не нужен: `workers_dev = true` даёт бесплатный адрес
`escx-api.<поддомен>.workers.dev`. Свой домен подключается позже — заменить
`SITE_URL` и раскомментировать `routes`.

**Почта обязательна.** `REQUIRE_VERIFIED_EMAIL = "1"` в `wrangler.toml` требует
подтверждённый адрес: регистрация заводит аккаунт, но сессию не выдаёт, пока человек
не откроет ссылку из письма. Без рабочего `RESEND_API_KEY` не сможет войти никто —
сначала почта по `docs/08-mail.md`, потом деплой.

Механика от почты не зависит и её можно проверить заранее: поставьте флаг в `"0"`,
и вход по паролю заработает сразу, а письма будут уходить в лог Worker.

## Ручки

| метод и путь | что делает |
|---|---|
| `POST /api/register` | завести аккаунт: адрес и пароль, сразу выдаёт сессию |
| `POST /api/signin` | войти |
| `POST /api/logout` | выйти |
| `GET /api/me` | кто я, тариф, подтверждён ли адрес, включены ли уведомления |
| `POST /api/password/forgot` | прислать ссылку на смену пароля |
| `POST /api/password/reset` | задать пароль по ссылке из письма |
| `POST /api/password/change` | сменить пароль, зная текущий |
| `POST /api/notify` | согласие на уведомления |
| `GET /api/verify?token=` | подтвердить адрес по ссылке из письма |
| `POST /api/verify/resend` | выслать письмо подтверждения заново (нужен пароль) |
| `GET /api/data` | витрина с учётом тарифа |
| `POST /api/webhook` | вебхук платёжной системы |

## Что где

| Файл | Отвечает за |
|---|---|
| `src/index.js` | маршруты, CORS, обработка вебхука, отправка писем |
| `src/auth.js` | регистрация, вход, сессии, сброс пароля, счётчик попыток |
| `src/password.js` | **хэширование пароля; читать шапку до правок** |
| `src/billing.js` | проверка подписи вебхука, разбор события подписки |
| `src/entitlement.js` | **единственное место, где решается, что доступно** |
| `src/util.js` | HMAC, хэши, сравнение за постоянное время, cookie |
| `schema.sql` | таблицы D1 |

## Правила, которые нельзя нарушать

1. **Тело вебхука берётся сырым.** Распарсить и собрать обратно — подпись не сойдётся.
2. **Подписи сравниваются за постоянное время.** Обычное `===` позволяет подобрать
   подпись побайтно по времени ответа.
3. **Токены и пароли хранятся только в виде хэша.** Дамп базы не должен давать вход.
4. **Проверка доступа только через `planFor` + `applyLimits`.** Не дублировать в обработчиках.
5. **Ответ на `/api/signin` одинаков для неверного пароля и незнакомого адреса** —
   иначе форма входа превращается в способ узнать, кто у нас зарегистрирован.
   Одинаков и по тексту, и по времени: за этим следит `burnTime` в `password.js`.
   Правило относится ко входу; `/api/register` про занятый адрес говорит прямо,
   потому что соврать здесь значит отправить человека ждать письма, которого не будет.
6. **Источник истины об оплате — платёжная система.** База лишь кэш её решений.
7. **`AUTH_PEPPER` не менять после первого запуска.** Он не хранится в базе; новый
   перец означает, что ни один существующий пароль не подойдёт.
8. **Смена и сброс пароля убивают все сессии адреса.** Иначе смена пароля не выгоняет
   того, из-за кого её делают.
9. **Повторная отправка письма подтверждения требует пароль.** Ручка «пришлите письмо
   на этот адрес» без пароля — готовый способ засыпать чужой ящик нашими письмами
   и заодно испортить репутацию домена, с которого уходят письма всем остальным.
