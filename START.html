А. Положить проект на GitHub

15 минут · бесплатно

GitHub нужен по двум причинам: оттуда Cloudflare берёт файлы сайта, и там же бесплатно работает робот, собирающий данные.

папка escx с файлами внутри
2

github.com/signup
вы вошли и видите свою страницу профиля
3
Скачать и установить GitHub Desktop, войти в нём своим аккаунтом.
desktop.github.com
Так не нужен терминал. Если предпочитаете команды — см. карточку «Через терминал» в конце.
4
В GitHub Desktop: File → Add local repository → выбрать папку escx.
программа видит папку и показывает историю изменений
5
Нажать Publish repository. Снять галочку «Keep this code private». Подтвердить.
репозиторий открывается на github.com и помечен Public
Галочку снимаем не из идеализма: у публичного репозитория робот работает без ограничения по времени, у приватного — 2000 минут в месяц.

github.com → ваш репозиторий → вкладка Actions

Б. Поднять сайт на Cloudflare Pages

10 минут · бесплатно, карта не нужна

Домен здесь не нужен. На выходе получите рабочий адрес, который уже можно показывать.

7
Зарегистрироваться в Cloudflare, подтвердить почту.
dash.cloudflare.com/sign-up
8
В левом меню выбрать Compute (Workers & Pages).
9
Нажать Create → переключиться на вкладку Pages → Connect to Git.
Самая частая ошибка во всей инструкции. Cloudflare открывает вкладку Workers первой, и она выглядит как единственный вариант. Worker — это программа, обрабатывающая запросы; сайт он показывать не умеет. Проверить, что попали куда надо, можно по адресной строке: у Pages в ней есть /pages/, у Worker — /workers/services/. Если увидели вкладки Bindings и Observability и метрику «Invocations» — это Worker, вернитесь и выберите Pages.
10
Разрешить Cloudflare доступ к GitHub, в списке выбрать репозиторий escx, нажать Begin setup.
11
Заполнить настройки сборки. Остальное не трогать.
Project name:              escx
Production branch:         main
Build command:             python3 web/build.py
Build output directory:    site
12
Раскрыть Environment variables и добавить одну переменную.
PYTHON_VERSION = 3.11
Без неё сборка упадёт: по умолчанию там старый Python.
13
Нажать Save and Deploy и подождать 1–3 минуты.
зелёная надпись Success и ссылка вида escx.pages.dev
14
Открыть эту ссылку и убедиться, что сайт работает.
страница с дугой, числом и списком диад; сверху плашка «демонстрационные данные»
Плашка — это нормально. Робот ещё не накопил настоящих данных, она сменится сама.

В. Домен: серверы имён

10 минут + ожидание

Домен покупается у Google, а управлять им будет Cloudflare. Для этого в форме Google указываются серверы имён Cloudflare — но сначала их надо получить.

15
В Cloudflare вверху нажать + Add → Existing domain (в старом интерфейсе — Add a site).
16
Ввести имя домена без https:// и без www. Например brink.watch.
17
Выбрать план Free — он в самом низу списка — и продолжить.
Платные планы предлагаются первыми и выглядят как обязательные. Бесплатного хватает полностью.
18
Cloudflare покажет два сервера имён. Выписать обе строки целиком.
ada.ns.cloudflare.com
rick.ns.cloudflare.com
Это пример. У вашего аккаунта имена будут другие — берите те, что показаны у вас.
19
Вернуться в форму Google. В разделе DNS configuration оставить Use custom name servers и вписать обе строки в поля Name server 1 и Name server 2.
красные подписи «cannot be empty» исчезли
20
Заполнить Privacy protection — выбрать скрытие контактных данных.
21
Заполнить Contact details — реальные имя, адрес, телефон, почта.
Данные должны быть настоящими: за выдуманные домен могут разделегировать. Приватность их всё равно скроет от посторонних.
22
Оплатить регистрацию.
домен появился в списке ваших доменов у Google
23
Вернуться в Cloudflare и нажать Check nameservers now. Дальше ждать.
статус домена меняется на Active; приходит письмо
Обычно 5–30 минут, иногда до суток. Это нормально и от вас не зависит — просто периодически проверяйте.

Чтобы пошли данные — три кнопки

Сбор устроен так, что после первого запуска он идёт сам. Но первый запуск нужно сделать руками, и порядок здесь важен.

1. Разовый исторический прогон. GitHub → вкладка Actions → слева backfill → справа Run workflow → зелёная кнопка Run workflow. Годы можно не трогать.

через 10–30 минут напротив прогона зелёная галочка, а в репозитории появляется коммит «бэкфилл»

Почему без него нельзя. Накал — это отклонение от нормы, а норма считается по прошлому самой пары. Без истории первое число оказывается отклонением от самого себя, то есть ровно пятьюдесятью у всех.

2. Проверить, что сайт ожил. Откройте brink.watch и обновите страницу с Ctrl+Shift+R.

вместо «Пайплайн собирает данные» — числа, фазы и спидометр

3. Включить расписание. На вкладке Actions убедитесь, что прогоны daily и pull-gdelt не отключены (у отключённых рядом написано Disabled, включаются кнопкой Enable workflow).

daily раз в сутки досчитывает и публикует, pull-gdelt раз в час собирает свежие новости
GitHub отключает расписания после 60 дней без активности в репозитории. Ежедневный прогон сам коммитит снимок данных — активность есть, и отключения не происходит.

Что будет на сайте после первого прогона. Не всё сразу, и это нормально:

Из пяти блоков накала работают два — боевые события (UCDP) и медиапоток (GDELT). Военный, дипломатический и экономический блоков источников пока не имеют, поэтому у каждой пары написано покрытие 40 %, а числа приглушены. Это сделано намеренно: два блока не выдаются за пять.

50 — это норма для пары, а не половина пути к войне. Накал показывает отклонение от обычного для этой пары уровня. У спокойной пары он и будет около 50.

Глобальный спидометр появляется только после того, как загрузятся доли населения, ВВП и военных расходов — это делает тот же прогон, шагом «веса последствий». Если Всемирный банк в этот момент недоступен, на месте индекса останется прочерк до следующего прогона. Прочерк здесь честнее числа.

Как обновить сайт после изменений

Сначала выясните, какого типа ваш проект Pages. От этого зависит всё остальное, и именно здесь чаще всего теряют время: файлы на GitHub поменялись, а сайт остался прежним.

Cloudflare → Compute (Workers & Pages) → ваш проект → вкладка Deployments. Посмотрите на строку последней сборки:

Написано Direct Upload
Проект живёт загруженным архивом и про GitHub ничего не знает. Сколько ни меняйте файлы в репозитории, сайт не изменится — это не поломка, так устроен этот тип проекта. Два выхода — ниже.
Написана ветка и номер коммита (main · a1b2c3d)
Проект связан с GitHub и пересобирается сам. Если сайт всё равно старый — смотрите «Сборка прошла, а сайт прежний» ниже.
Ветка в строке сборки — не та, в которую вы пушите
Cloudflare следит ровно за одной веткой. По умолчанию он ставит main, а в вашем репозитории ветка называется master — тогда пуш проходит, а сборка не запускается вообще. Лечится в Settings → Builds → Production branch: поставить master. Проверить имя ветки можно на GitHub — оно написано на кнопке-переключателе слева над списком файлов.

Выход 1 — связать проект с GitHub раз и навсегда. Рекомендуется: дальше достаточно будет менять файлы в репозитории.

В проекте: Settings → Builds → Connect to Git → выбрать репозиторий. Затем заполнить настройки сборки ровно так:

Production branch          master        <- как называется ветка в репозитории
Build command              python3 web/build.py
Build output directory     site
Root directory             (оставить пустым)

И переменную окружения: Settings → Variables and Secrets → PYTHON_VERSION = 3.11. Без неё сборка упадёт. После этого — Deployments → Retry deployment, и через минуту-две сайт обновится.

Если команда сборки не задана, а Build output directory оставлен пустым, Cloudflare публикует корень репозитория как есть. Это тоже рабочая схема — при ней собранные файлы (index.html, папка data/, иконки) должны лежать в корне репозитория. Положить их туда: python3 web/build.py --to-root.

Выход 2 — загрузить новый архив руками. Быстрее один раз, но повторять придётся при каждом изменении.

Соберите папку: python3 web/build.py, упакуйте содержимое папки site/ (не саму папку) в zip. Затем: проект → Deployments → Create deployment → перетащить архив → Deploy.

Кнопки Create deployment нет, если проект связан с Git: у таких проектов деплой создаётся только пушем. Это признак, по которому тип проекта видно и без вкладки Deployments.

Домен открывает старый сайт, а новый — только на *.pages.dev
Домен привязан к другому проекту. Один домен может принадлежать только одному проекту сразу. Откройте каждый проект → Custom domains и найдите, в каком из них числится brink.watch. Обновлять надо именно его — либо снять домен там и добавить в нужном.
Сборка прошла, а сайт прежний
Сначала проверьте, что сборка действительно Success, а не Failed: при неудаче Cloudflare оставляет в эфире прошлую удачную версию, и внешне это выглядит как «ничего не произошло». Если Success — обновите страницу с Ctrl+Shift+R (Cmd+Shift+R на Mac): браузер держит копию. Не помогло — Cloudflare → домен → Caching → Configuration → Purge Everything.

Если пошло не так

Сборка упала с ошибкой про Python
Не добавлена переменная PYTHON_VERSION = 3.11 (шаг 12). Settings → Environment variables, добавить и запустить сборку заново кнопкой Retry deployment.
Сайт открылся, но пустой и без чисел
Скорее всего указана не та папка. В настройках сборки Build output directory должно быть ровно site.
Домен в Cloudflare сутки висит «Pending»
Серверы имён у Google прописаны с опечаткой или не сохранились. Откройте домен в Google Cloud Domains → DNS и сверьте обе строки посимвольно с тем, что показывает Cloudflare.
Создал проект, а вместо сайта — вкладки Bindings, Observability и «Latest build failed»
Это Worker, а не Pages: их легко перепутать на шаге 9. Worker сайт показывать не умеет. Создайте заново через Create → вкладка Pages, дав другое имя проекта, чтобы не конфликтовало со старым. Ненужный Worker удаляется в Settings → Delete.
Вкладка Actions пустая
Не нажата зелёная кнопка включения (шаг 6). Без неё робот не запустится, но на работу сайта это не влияет.
Cloudflare не даёт добавить домен на шаге 15
Бывает, пока домен не зарегистрирован. Тогда в форме Google включите Cloud DNS, завершите покупку, а потом вернитесь к шагам 15–19: серверы имён меняются в любой момент после регистрации.

Быстрый путь: без GitHub, загрузкой архива

Если хочется увидеть сайт живым прямо сейчас, блоки А и Б можно пропустить. Возьмите готовый архив escx-site.zip и загрузите его напрямую:

Compute (Workers & Pages) → Create → вкладка Pages → Upload assets → имя проекта → перетащить архив не распаковывая → Deploy site.

Минус один: обновляться сам такой сайт не будет, для изменений надо загружать архив заново. Подключить GitHub можно позже — Settings → Builds → Connect to Git, адрес при этом не меняется.

Собрать архив самому: python3 web/build.py --demo, затем упаковать содержимое папки site/ — именно содержимое, а не саму папку.

Публичный репозиторий — не страшно, но выбор за вами

Да, публичный репозиторий видят все, и код может скопировать кто угодно. Но код здесь — не то, что вас защищает: это пара тысяч строк простого Python и JavaScript, грамотный разработчик повторит их за две недели.

Защищает другое: журнал калибровки, который копится полтора года и не копируется в принципе; выверенный вручную реестр диад; домен, имя и аудитория; и просто то, что вы делаете это каждый день, а копирующий — нет.

Больше того: открытая методология и есть главный аргумент продукта. У RANE и Verisk она закрыта — именно поэтому им нельзя задать вопрос «а почему 79?». Спрятав свою, вы теряете то, чем отличаетесь.

Если всё равно некомфортно — делайте приватным, это рабочий вариант. Cloudflare Pages подключается к приватным репозиториям без проблем. Цена: 2000 минут Actions в месяц вместо безлимита, поэтому в .github/workflows/hourly.yml надо поменять расписание на "7 */3 * * *" — раз в три часа вместо часа. На точность это почти не влияет: горизонты у нас месячные.

Разумный компромисс: код приватный, а папку docs/ — методологию — выложить отдельно или просто страницей на сайте. Тогда и проверяемость на месте, и внутренности закрыты.

Через терминал, если так привычнее

Шаги 3–5 заменяются двумя командами. Нужен установленный GitHub CLI.

cd escx
gh repo create escx --public --source=. --push

Сколько это стоит

Блоки А, Б, Г, Д — ноль. Единственная трата — домен в блоке В, примерно $12 в год.

Если домен пока не нужен, блоки В и Г можно пропустить целиком: сайт работает на бесплатном адресе escx.pages.dev, и домен подключается к нему в любой момент позже.

Обоснование выбора хостинга — docs/06-deploy.md. Подписки и доступ — docs/07-billing.md.
