# Публикация сайта: бесплатно и без сервера

**Escalation Index** · август 2026

---

## 1. Почему это вообще может быть бесплатным

Обычный дашборд стоит денег, потому что на каждый запрос пользователя он ходит в базу.
Значит, нужен сервер, база и оплата за то, что они работают круглые сутки.

Здесь этого нет. Пайплайн раз в сутки считает всё заранее и складывает результат
в SQLite. Скрипт `web/build.py` выгружает витрину в несколько JSON-файлов и собирает
папку `site/` — обычную статику. Браузер забирает JSON и рисует интерфейс сам.

```
GitHub Actions (раз в сутки)
    ↓  пересчёт → SQLite
web/build.py
    ↓  JSON + HTML → site/
статический хостинг
    ↓
пользователь
```

Ни сервера, ни базы, ни бэкенда. Платить не за что — вопрос только в том, чей
бесплатный тариф выбрать.

## 2. Сравнение бесплатных тарифов

| | GitHub Pages | Cloudflare Pages | Netlify | Vercel Hobby |
|---|---|---|---|---|
| Цена | 0 | 0 | 0 | 0 |
| Трафик | 100 ГБ/мес, мягкий лимит | лимит не заявлен | 100 ГБ/мес | ~100 ГБ/мес |
| Размер сайта | 1 ГБ | 20 000 файлов, до 25 МиБ файл | — | — |
| Сборки | без лимита через Actions | 500/мес, 1 одновременно | 300 мин/мес | — |
| Свой домен | да, HTTPS бесплатно | да, 100 доменов | да | да |
| **Коммерческое использование** | **запрещено** | **разрешено** | разрешено | **запрещено** |

**Главное — последняя строка, и её обычно не читают.**

GitHub Pages в условиях прямо сказано: сервис «не предназначен и не может
использоваться как бесплатный хостинг для ведения онлайн-бизнеса, интернет-магазина
или любого сайта, направленного преимущественно на совершение коммерческих операций
или предоставление коммерческого ПО как услуги».

Vercel Hobby в правилах добросовестного использования ограничен «некоммерческим,
личным использованием».

У нас в бизнес-плане есть тарифы Pro за $29 и API за $299. Как только на сайте
появится кнопка оплаты, обе площадки формально нарушены.

## 3. Рекомендация

**Начать на Cloudflare Pages.**

Единственная из четырёх, где бесплатный тариф не запрещает коммерческое
использование и не заявляет лимит трафика. Переезжать потом — лишняя работа
и риск потерять позиции в поиске на смене домена, поэтому проще сразу встать там,
где можно остаться.

GitHub Pages годится, пока сайт — публичная витрина без единой платной кнопки:
настройка занимает две минуты, потому что репозиторий и Actions уже на GitHub.
Но это временное решение с известным сроком годности.

Обе конфигурации лежат в репозитории — переключение стоит одного коммита.

## 4. Как запустить

### Шаг 0. Локально, чтобы убедиться

```bash
python3 web/build.py --demo
python3 -m http.server -d site 8000
# открыть http://localhost:8000
```

Сборка работает и без базы: если пайплайн ещё не наполнил SQLite, сайт соберётся
на демо-данных и покажет об этом плашку. Это сделано намеренно — деплой должен
работать с первого дня, а не после того, как накопятся данные.

### Шаг 1. Репозиторий на GitHub

```bash
gh repo create escx --public --source=. --push
```

Публичный репозиторий даёт **бесплатные минуты Actions без ограничений**.
У приватного на бесплатном тарифе — 2000 минут в месяц; нашему пайплайну этого
тоже хватает с запасом, но публичный ещё и работает на доверие: методологию можно
проверить, а это главный аргумент продукта.

### Шаг 2а. Cloudflare Pages — рекомендуемый путь

1. [dash.cloudflare.com](https://dash.cloudflare.com/) → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. Выбрать репозиторий `escx`
3. Настройки сборки:
   - **Build command:** `python3 web/build.py`
   - **Build output directory:** `site`
   - **Environment variables:** `PYTHON_VERSION` = `3.11`
4. **Save and Deploy**

Через минуту сайт живёт на `escx.pages.dev`. Дальше каждый push в `main`
пересобирает автоматически.

### Шаг 2б. GitHub Pages — если пока без монетизации

1. **Settings → Pages → Source: GitHub Actions**
2. Всё. Workflow `.github/workflows/deploy.yml` уже в репозитории.

Сайт появится на `<логин>.github.io/escx/`. Пересборка — на каждый push
и раз в сутки по расписанию, через полчаса после ежедневного пересчёта данных.

### Шаг 3. Свой домен

Домен — единственная статья расходов во всей схеме: примерно **$10–15 в год**.
Регистратор любой; у Cloudflare домены продаются по себестоимости без наценки
за продление, что для долгого проекта заметно.

- **Cloudflare Pages:** проект → **Custom domains** → **Set up a domain**. Если домен
  уже в Cloudflare, DNS проставится сам. HTTPS бесплатно.
- **GitHub Pages:** файл `CNAME` в корне `site/` (добавьте копирование в `build.py`),
  затем **Settings → Pages → Custom domain** и галочка **Enforce HTTPS**.

## 5. Что окажется в счёте на самом деле

| Статья | В месяц |
|---|---|
| Хостинг сайта | **0** |
| Прогоны пайплайна (публичный репозиторий) | **0** |
| Хранение артефактов | **0** в пределах бесплатного объёма |
| Домен | ~$1 (около $12 в год) |
| BigQuery для исторического GDELT | 0 в пределах 1 ТБ/мес, дальше платно |
| LLM-скоринг живого потока | ~$60, либо 0 на локальной модели |

**Пока нет LLM-скоринга и тяжёлых запросов в BigQuery, проект стоит примерно
доллар в месяц.** Это существенно ниже прежней оценки в $200: та закладывала
управляемую базу, приложение на Vercel Pro и облачный LLM. Статическая архитектура
убирает первые две статьи целиком.

Точка безубыточности при этом падает с семи подписок практически до нуля —
проект перестаёт требовать денег и начинает требовать только времени.

## 6. Когда бесплатного перестанет хватать

Честные границы, чтобы не упереться неожиданно:

- **Личный кабинет и платные тарифы.** Статике негде хранить, кто что оплатил.
  Нужен бэкенд — но не раньше, чем появится первый платящий. Дешёвый следующий шаг:
  Cloudflare Workers (100 000 запросов в сутки бесплатно) плюс Stripe.
- **Алерты по почте.** Отправка писем со статики невозможна. Первый бесплатный
  вариант — Resend или Brevo в пределах бесплатного объёма, вызов из того же
  ежедневного прогона Actions.
- **Трафик.** 100 ГБ в месяц для страницы весом ~150 КБ — это порядка 600 тысяч
  просмотров. На Cloudflare лимит вообще не заявлен. Раньше этого упрётся что-то другое.
- **История по каждой диаде.** Пока в JSON лежат 90 точек. Полная пятилетняя история
  по 60 диадам — это десятки мегабайт; их стоит вынести в отдельные файлы и грузить
  по требованию, а не класть в общий индекс.
