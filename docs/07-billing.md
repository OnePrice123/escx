## 1. Почему не сервер на Google Cloud

Вопрос был именно про него, поэтому начну с цифр, а не с мнения.

| | Cloudflare Workers + D1 | Google Cloud e2-micro |
|---|---|---|
| Цена при нашей нагрузке | **$0** | $0 в пределах Always Free |
| Запросов в сутки | 100 000 | не ограничено |
| **Исходящий трафик** | не тарифицируется по гигабайтам | **1 ГБ в месяц** |
| География | 330+ городов | 3 региона США |
| База данных | D1 включена: 5 ГБ, 5 млн чтений в сутки | ставить и обслуживать самому |
| Обслуживание | нет | ОС, TLS, nginx, мониторинг, бэкапы — ваши |
| Карта при регистрации | не нужна | обязательна |

**Ключевая строка — трафик.** Один гигабайт в месяц при странице весом 150 КБ — это примерно 6 600 просмотров, дальше начинается счёт. Бесплатный VM в Google Cloud упрётся в лимит раньше, чем вы получите первого платящего клиента. Cloud Run не спасает: там тот же гигабайт.

Плюс три региона США означают заметную задержку для европейского читателя, а обслуживание виртуалки — это работа, которая никогда не заканчивается: обновления, сертификаты, мониторинг, разбор ночных падений. Для соло-проекта это самая дорогая статья, просто она измеряется не в долларах.

**Вывод: сервер не нужен ни для сайта, ни для подписок.** Ниже — то, что нужно.

## 2. Как устроено

```
Статика на Cloudflare Pages                     бесплатно, без лимита трафика
   └── публичная витрина: 20 диад, задержка сутки

Cloudflare Worker                               бесплатно до 100 000 запросов/сутки
   ├── POST /api/login      письмо со ссылкой для входа
   ├── GET  /api/verify     обмен ссылки на сессию
   ├── GET  /api/me         кто я и что оплачено
   ├── GET  /api/data       витрина с учётом тарифа
   └── POST /api/webhook    событие об оплате от платёжной системы

D1 (SQLite на периферии)                        бесплатно: 5 ГБ, 5 млн чтений/сутки
   └── subscriptions · sessions · magic_links · webhook_log

Paddle                                          комиссия с оборота, без абонплаты
   └── оплата, продления, налоги
```

**Публичная часть не проходит через Worker вообще.** Бесплатный лимит тратится только на тех, кто платит или собирается — то есть на доли процента посетителей. Это и делает схему бесплатной не «на старте», а надолго.

### Пять решений, которые стоит понимать

**Паролей нет.** Вход по одноразовой ссылке из письма. Пароль, которого мы не храним, невозможно у нас украсть. Для инструмента, куда заходят раз в неделю, это не компромисс, а удобнее.

**В базе лежат только хэши.** И токен из письма, и идентификатор сессии хранятся как SHA-256. Утечка дампа базы не даёт войти ни под кем.

**Источник истины об оплате — платёжная система, а не наша база.** База лишь кэширует её решения. Поэтому подписка считается действующей, только если платёжка сказала «активна» **и** оплаченный период ещё не кончился: достаточно одному условию отвалиться.

**Проверка доступа в одном месте.** Файл `entitlement.js`, функции `planFor` и `applyLimits`. Если проверку размазать по обработчикам, однажды её забудут в одном — и закрытые данные утекут.

**Вебхуки идемпотентны.** Платёжная система перепосылает событие при сбое сети. Журнал `webhook_log` по `event_id` не даёт обработать одно и то же дважды.

## 3. Paddle или Stripe

| | Stripe | Paddle |
|---|---|---|
| Абонплата | нет | нет |
| Комиссия | 2.9 % + 30¢, плюс 0.7 % за подписки | 5 % + 50¢ |
| С $29 остаётся | **$27.66** | $27.05 |
| НДС и налог с продаж | **ваша забота** | берёт на себя |
| Юридический продавец | вы | Paddle |

Разница в деньгах — 61 цент с подписки. При шестидесяти подписчиках это около $37 в месяц.

**Рекомендую Paddle.** Он выступает продавцом записи (merchant of record): регистрирует, декларирует и платит НДС и налоги с продаж за вас по всем странам. Для соло-основателя, продающего цифровую услугу по всему миру, это снимает настоящую юридическую обязанность — при продажах в ЕС требуется регистрация по НДС и ежеквартальная отчётность. Бухгалтер обойдётся дороже тех $37, не считая риска ошибиться.

Переключение между ними — одна переменная `PROVIDER` в настройках: проверка подписи написана для обоих.

**Оговорка:** доступность Paddle и Stripe зависит от страны регистрации. Проверьте свою в их списках до того, как строить на этом планы.

## 4. Сколько это стоит

| Статья | В месяц |
|---|---|
| Cloudflare Pages — сайт | $0 |
| Cloudflare Workers — API | $0 (100 000 запросов в сутки) |
| Cloudflare D1 — база | $0 (5 ГБ, 5 млн чтений в сутки) |
| Resend — письма | $0 (3 000 писем в месяц) |
| Paddle | только процент с поступлений |
| **Постоянные расходы** | **$0** |

Комиссия платёжки — единственная статья, и она берётся с денег, которые уже пришли. **Пока никто не заплатил, не платите и вы.**

Запас по лимитам: 100 000 запросов в сутки при десяти запросах на визит — это 10 000 визитов в день. Упрётесь во что угодно другое раньше.

## 5. Настройка

```bash
npm install -g wrangler
cd api
wrangler login

# база
wrangler d1 create escx                 # id из вывода вписать в wrangler.toml
wrangler d1 execute escx --file=schema.sql --remote

# секреты: в файлы не попадают, лежат на стороне Cloudflare
wrangler secret put PADDLE_WEBHOOK_SECRET   # из настроек уведомлений Paddle
wrangler secret put RESEND_API_KEY

wrangler deploy
```

В Paddle: **Developer tools → Notifications → New destination**, адрес `https://<ваш-домен>/api/webhook`, события `subscription.created`, `subscription.updated`, `subscription.canceled`. Секрет оттуда положить в `PADDLE_WEBHOOK_SECRET`.

Проверить локально, без сети и без облака:

```bash
node api/test/test.mjs      # 166 проверок
```

## 6. Когда бесплатного перестанет хватать

- **Более 100 000 запросов к API в сутки.** Платный тариф Workers снимает лимит; при таком трафике деньги уже есть.
- **Более 3 000 писем в месяц.** Дальше платный тариф Resend или другой отправитель.
- **Более 100 000 записей в базу в сутки.** Нам столько не понадобится: пишем только при оплате и при входе.
