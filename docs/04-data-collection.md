# Сбор данных: чем и как

**Escalation Index** · практическое руководство к разделу 7 методологии
Версия 0.1 · август 2026

К этому документу приложен рабочий код: `escx-ingest.zip`. Он запускается без единой установки пакетов — только стандартная библиотека Python 3.11.

---

## 1. Три режима получения данных

Первое, что стоит понять: источники делятся не по темам, а по **режиму доступа**. От этого зависит и код, и расписание, и расходы.

| Режим | Кто | Как устроено | Такт опроса |
|---|---|---|---|
| **API с пагинацией** | UCDP, FAA NOTAM, Comtrade | HTTP-запрос → JSON, страницами | раз в сутки |
| **Файловый поток** | GDELT (каждые 15 мин), OFAC, UK OFSI | архив по предсказуемому URL | GDELT — раз в час, санкции — раз в сутки |
| **Разовая выгрузка** | GPR, SIPRI, голосования ГА ООН | один файл, обновляется редко | GPR — раз в неделю, SIPRI — раз в год |

Половина пайплайна может ходить в источники редко. Это не мелочь: разница между «опрашиваем всё каждые 15 минут» и «опрашиваем по режиму источника» — примерно вся разница в счетах за инфраструктуру.

## 2. Что откуда берётся

| Блок | Индикатор | Источник | Инструмент | Лимиты и цена |
|---|---|---|---|---|
| **1. Кинетика** | боевые события, погибшие, география | UCDP GED | REST API, пагинация | бесплатно, без ключа; 5000 запр./сут на IP, ≤1000 строк на страницу |
| | текущий год | UCDP Candidate | тот же API | бесплатно; **данные предварительные, пересматриваются** |
| **2. Военные приготовления** | учения, мобилизация, боеготовность | новостной поток | GDELT + LLM-извлечение | GDELT бесплатно; LLM — основная переменная расходов |
| | закрытие воздушного пространства | NOTAM | FAA NOTAM API (ключ бесплатный), нац. AIP | бесплатно с регистрацией; единого мирового API нет |
| | военные расходы | SIPRI Milex | XLSX, раз в год | бесплатно, атрибуция |
| **3. Дипломатия** | баланс конфликт/кооперация | GDELT Events, CAMEO + Goldstein | файловый поток или BigQuery | GDELT бесплатно; BigQuery — 1 ТБ/мес бесплатно, дальше платно |
| | голосования ГА ООН | UN Digital Library / набор Вутена (Harvard Dataverse) | CSV, раз в год | бесплатно |
| | отзыв послов, разрыв соглашений | новостной поток | GDELT + LLM | см. выше |
| **4. Экономическое давление** | санкционные меры | OFAC SDN, консолидированный ЕС, UK OFSI | CSV/XML по прямой ссылке | бесплатно |
| | двусторонняя торговля | UN Comtrade | REST API | бесплатный тариф с лимитом; данные с лагом |
| **5. Информационное поле** | объём и тон покрытия | GDELT GKG | BigQuery (gkg_partitioned) | таблица 3.6 ТБ — только с фильтром по дате |
| | семантический скоринг риторики | LLM по отфильтрованным материалам | батч + кэш | ~$60/мес при MVP-объёме |
| | внешний ориентир | GPR Index (Caldara & Iacoviello) | XLS, месячный и дневной | бесплатно, **CC BY** |

**ACLED в этой таблице нет намеренно.** Его условия прямо запрещают использовать контент для оказания услуг третьим лицам, создавать конкурирующие датасеты и обучать на нём модели-заменители. Проект нашего типа попадает под все три пункта. Это архитектурное ограничение: ни одного байта ACLED в пайплайне до отдельного коммерческого договора.

## 3. Инструменты по слоям

Выбор в одну строку: **скучный стек**. Соло-разработчик не может позволить себе отладку экзотики, и операционная стоимость Kafka или Airflow съест весь бюджет времени раньше, чем даст пользу.

| Слой | Чем | Почему именно так |
|---|---|---|
| HTTP | `urllib` из стандартной библиотеки + своя обёртка с ретраями, бэкоффом и дисковым кэшем | нулевые зависимости; кэш экономит лимит UCDP, который исчерпывается при отладке быстрее, чем кажется |
| Парсинг | `csv`, `zipfile`, `json` — всё стандартное | GDELT отдаёт tab-separated внутри zip без заголовка; pandas тут ничего не добавляет |
| Хранилище | **SQLite** на старте → Postgres при росте | 60 диад × 365 дней × 40 индикаторов ≈ миллион строк в год. SQLite держит это с запасом и ставится нулём команд. Схема написана так, что переносится в Postgres заменой трёх типов |
| Аналитика | DuckDB локально для бэктестов | читает те же файлы, считает оконные функции на ноутбуке без облачных счетов |
| Оркестрация | **GitHub Actions по расписанию** | ноль инфраструктуры, бесплатно для приватного репозитория в пределах лимита, логи и алерты из коробки |
| Исторический бэкфилл GDELT | **BigQuery** | собрать год через файловый поток — это ~35 000 архивов. BigQuery делает то же одним запросом |
| LLM-скоринг | дешёвая модель, батч, кэш по хэшу текста | подход AI-GPR: семантическая оценка вместо ключевых слов. Ключевая статья расходов, поэтому жёсткий дневной лимит прямо в коде |

## 4. Пять ловушек, на которых это ломается тихо

Все пять объединяет одно: они **не вызывают ошибки**. Пайплайн работает, цифры считаются, графики рисуются — и всё неверно.

### 4.1 Три несовместимые системы кодов стран

| Источник | Система | Индия | Германия | Филиппины |
|---|---|---|---|---|
| UCDP | Gleditsch & Ward | `750` | `260` | `840` |
| GDELT | CAMEO (по сути FIPS) | `IND` | `GER` | `RP` |
| SIPRI, Comtrade, IMF | ISO 3166-1 alpha-3 | `IND` | `DEU` | `PHL` |

Совпадение `IND` у CAMEO и ISO3 — случайность, и она усыпляет бдительность. У Германии и Филиппин коды расходятся полностью. Без явной таблицы соответствий события молча приписываются не тем диадам.

Решение: одна таблица, ведётся руками, версионируется, покрыта тестом. В приложенном коде — `escx/codes.py`.

### 4.2 GDELT: одно событие — много записей

`GLOBALEVENTID` не уникален во времени. Один и тот же сюжет переизлагается и попадает в несколько 15-минутных срезов. Без дедупликации по естественному ключу кинетика раздувается пропорционально медиавниманию — то есть ровно тому, что мы пытаемся из индекса убрать.

Решение: первичный ключ `(source, source_id)` и `INSERT OR IGNORE`. Повторный прогон того же файла становится безопасным, а пайплайн — идемпотентным.

### 4.3 UCDP: финальные данные и предварительные — разные вещи

GED выходит **раз в год** (версия 25.1 = данные по 2024 включительно). Для текущего года есть UCDP Candidate — предварительные ежемесячные данные, которые **потом пересматриваются задним числом**.

Если смешать их в обучающей выборке, модель будет обучаться на пересмотренных значениях — то есть знать будущее. Метрики выйдут блестящие, а на живых данных модель развалится. Это классическая утечка, и в задачах прогноза конфликтов она встречается постоянно.

Решение: разные значения в поле `source` (`ucdp_ged` против `ucdp_candidate`), обучение только на финальных версиях.

### 4.4 Goldstein — не измерение, а справочник

Шкала Голдштейна — это **атрибут типа события** по справочнику CAMEO, а не измеренная интенсивность. «Осуждение» всегда −2.0, независимо от того, чьё оно и по какому поводу.

Усреднять его «в лоб» нельзя: одно упоминание в блоге получит тот же вес, что сюжет, разошедшийся по тысяче изданий. Обязательно взвешивание на `NumMentions` и нормировка на общий объём покрытия — иначе индекс становится трекером новостной повестки. Это то же самое правило 5 методологии, только с другой стороны.

### 4.5 Точность даты у UCDP

У части событий дата известна лишь с точностью до месяца или года — поле `date_prec` со значениями 3–5. Такие события нельзя класть в 30-дневные окна: они размажут кинетику по всему периоду.

Решение: сырьё сохраняем как есть, фильтруем на этапе расчёта индикаторов. Выбрасывать при загрузке нельзя — для годовых агрегатов эти события корректны.

## 5. Дисциплина пайплайна

Четыре механизма, без которых сбор данных превращается в свалку.

**Идемпотентность.** Естественный ключ `(source, source_id)` плюс `INSERT OR IGNORE`. Прогон можно перезапустить сколько угодно раз — результат один и тот же. Это важнее, чем кажется: половина инцидентов в таких пайплайнах чинится повторным запуском, и он должен быть безопасен.

**Инкрементальность.** Таблица `watermarks` хранит позицию последнего успешно обработанного среза по каждому источнику. Без неё каждый прогон тянет всё заново.

**Append-only не на честном слове.** В техплане записано, что `raw_events`, `phase_log` и `forecasts` только для вставки. В коде это триггеры БД: `UPDATE` и `DELETE` физически отклоняются. Дисциплина, которую нельзя нарушить случайно, — единственная работающая.

**Измерение атрибуции.** Каждое событие несёт `match_level`: `rule`, `geo`, `llm` или `unmatched`. Несопоставленные не выбрасываются, а считаются. Рост доли `unmatched` вдвое означает, что источник поменял формат или в реестре не хватает диады — это одна из ежедневных проверок.

## 6. Контроль расходов

Три статьи, каждая со своим стопом.

**BigQuery.** Бесплатный лимит Google — 1 ТБ обработанных данных в месяц. Таблица `gkg` весит 3.6 ТБ и сжигает его одним неаккуратным запросом. Правила: только партиционированные таблицы, только с фильтром `_PARTITIONTIME`, и **обязательный `--dry_run` перед каждым запросом**. Не запускать ни одного запроса, не увидев его цену.

**LLM.** Дешёвый фильтр релевантности отсекает ~95 % потока до скоринга, дальше кэш по хэшу текста и жёсткий дневной лимит расходов прямо в коде. Отдельное решение, экономящее $400–500 единоразово: **исторические признаки берутся из бесплатных GDELT tone и Goldstein, дорогой LLM-скоринг применяется только к живому потоку.** Обучать модель на дорогом историческом скоринге не нужно — для истории достаточно дешёвых сигналов.

**UCDP.** 5000 запросов в сутки на IP. При `pagesize=1000` это 5 миллионов строк в день — с запасом. Но при отладке лимит исчерпывается неожиданно быстро, поэтому дисковый кэш включён по умолчанию.

Итого при MVP-объёме: BigQuery ~$30, LLM ~$60, остальное бесплатно.

## 7. Порядок внедрения

Соответствует неделям 1–3 роадмапа из техплана.

| Шаг | Что делаем | Готово, когда |
|---|---|---|
| 1 | Реестр диад руками, 40–60 штук, с обоснованием включения каждой | `config/dyads.json` заполнен |
| 2 | Таблица соответствий кодов для всех стран реестра | тест на полноту зелёный |
| 3 | Схема БД с триггерами append-only | `python -m escx.cli init` отрабатывает |
| 4 | Бэкфилл UCDP GED с 1989 | «все события диады X за 2019 год» даёт корректный ответ |
| 5 | Разметка вручную 500 событий, замер точности атрибуции | точность измерена и опубликована |
| 6 | Живой поток GDELT, ежечасно | `watermarks` двигается, дублей нет |
| 7 | Исторический GDELT через BigQuery | помесячные ряды по всем диадам с 2015 |
| 8 | Редкие источники: GPR, санкции, голосования ООН | все пять блоков имеют хотя бы по одному индикатору |

**Шаг 5 нельзя пропускать.** Он выглядит скучной ручной работой, но это единственный способ узнать, врёт ли атрибуция. Если врёт — врёт всё, что построено выше, и никакая модель этого не исправит.

## 8. Приложенный код

```
escx-ingest/
├── escx/
│   ├── codes.py           таблица соответствий GW ↔ CAMEO ↔ ISO3
│   ├── http.py            ретраи, бэкофф, дисковый кэш
│   ├── db.py              схема SQLite + триггеры append-only
│   ├── dyads.py           реестр диад
│   ├── match.py           сопоставление событий с диадами, три уровня
│   ├── indicators.py      робастная нормализация, накал, темп
│   ├── cli.py             init / backfill-ucdp / pull-gdelt / status
│   └── sources/
│       ├── ucdp.py        GED через API
│       ├── gdelt.py       файловый поток + шаблон запроса BigQuery
│       └── simple.py      GPR, санкции, голосования ООН, SIPRI, NOTAM
├── config/dyads.json      16 диад для старта
├── tests/test_offline.py  46 проверок, все без сети
└── .github/workflows/     ежедневный и ежечасный прогоны
```

Запуск:

```bash
python3 tests/test_offline.py            # 46 проверок, сеть не нужна
python3 -m escx.cli init
python3 -m escx.cli backfill-ucdp --start 2020-01-01 --end 2024-12-31
python3 -m escx.cli pull-gdelt --slices 8
python3 -m escx.cli status
```

**Важная оговорка о проверке.** Логика покрыта 46 офлайн-тестами, и они проходят: разбор форматов, перевод кодов, сопоставление с диадами, нормализация, идемпотентность записи, срабатывание триггеров append-only. А вот **живые запросы к UCDP и GDELT из моей песочницы не выполнялись** — исходящая сеть здесь ограничена белым списком, и эти домены в него не входят. Код к сетевым источникам написан по опубликованным спецификациям (эндпоинты, параметры, форматы файлов и колонок сверены с документацией), но первый реальный прогон вам нужно сделать у себя. Начните с `backfill-ucdp` на коротком диапазоне — если формат ответа где-то разойдётся с ожиданиями, это вылезет сразу и на маленьком объёме.
